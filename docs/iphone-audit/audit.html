Desktop Regression Check

Every fix sits behind a phone or touch condition: max-width: 760px or narrower, hover: none, pointer: coarse, or a matching matchMedia check in script. Screenshots before and after were compared pixel by pixel.

  • Static pages: 40 full-page tiles of / and /projects at 1440 × 900 and 768 × 1024. No tile changed beyond the 10px dev-badge and pill-animation corners, which also differ between two runs of the unchanged site.
  • Interactions: 12 states at 1440, 1280, and 768 wide (contact modal open, row and copy hover, Copied, closed, hero bar hover, KYLLM open and typed, About, chip hover, Experience, footer), compared against an untouched copy of main. The only differences are the drawn cursor and a tooltip fade landing on different frames, which flip between runs.
  • Caught and fixed during the check: the timeline scroll-to-end first ran on every width, shifting desktop by 3px and hiding tablet labels; it now runs under 720px only. The About stacking first fired on tablet’s 472px column; its breakpoint is now 440px.
  • Build: tsc --noEmit clean, npm run lint 0 errors (21 existing image warnings), npm run build passes.

Checks That Passed

  • The contact sheet keeps the page behind it from scrolling.
  • Copy buttons work: the simulator clipboard held the email, then the phone number.
  • Footer photos reveal on tap and open full screen.
  • KYLLM answers stream with a stop button, then show sources and follow-up questions.
  • The /projects top bar stays pinned while scrolling.
  • Rotating to landscape causes no sideways scrolling.

Not Tested

  • Camera, microphone, file upload: the site uses none of them.
  • The Phone row (tel:): the simulator has no Phone app.
  • iOS Text Size and Safari page zoom.
  • iPhone 17e and a physical device.

Outside iPhone Scope

  • /projects sets dates, metrics, and chips in Geist Mono; AGENTS.md keeps Mono for code identifiers.
  • The KYLLM field says “Ask KYLLM about my work…” above an empty state that says “Ask me about Kyle’s work”.
  • The contact sheet pads with env(safe-area-inset-bottom), which is always 0 without viewportFit: "cover".
